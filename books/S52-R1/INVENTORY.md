Task 1 of `PIPELINE.md`, by the method in the specification §5, against frozen map `fc19c8bc-a216-4131-99fb-ebe3f19cec4a`; `python check/amendments.py --rung S52-R1` (run 2 Oct 2026) prints no amendment for S52-R1 and none for the bridge rung S52-R2, so no amendment id is owed and no `verify_at_intake` instrument enters `READY.md` from the amendments file. Serves: O1–O3 rung-1 outcomes, S1–S2 skills, B build target (one dataset analysed end to end in a single script that another person can run), G gate (the analysis reproduces from raw data with one command); P1–P5, R1–R3, B2 and G2 of S52-R2 only as far as rung 2 presupposes them. S52 has no prerequisite subject. **Book 0 teaches no programming and nothing about files, folders or software**: it never mentions a script, a file path, a package or a data file. What it lends is reading a table — what one row stands for (the unit of observation), what each column reports, its unit and its source (F1 `C39`), which is the floor tidy data is built on; a variable as a letter standing for a number (C1 `C15`), which is the first of three meanings of "variable" this book must keep apart (algebra, R object, column of a data frame); a function as input, rule, output with f(x) notation (C4 `C18`), which is exactly how R calls a function; mean, median, quartiles and spread (D5 `C28`) for summaries; graphs and axes (C5 `C19`) and the ways a figure misleads (F2 `C40`) for plotting; units and conversion (B1 `C09`, B2 `C10`, B6 `C14`, kg/m² for BMI); decimals and printed digits (A3 `C03`) and scientific notation (A6 `C06`, which R prints as 1e+06); percentages (A4 `C04`) for the empirical sections; the order-of-magnitude check (A8 `C08`) for checking data; checking a reference (F3 `C41`). Spreadsheets appear in Book 0 only in passing — a narrow cell printing 1.5E+06 (A6), printed comma grouping (A1), unchosen printed digits (A3), checking a spreadsheet formula column (C1) — and are never taught as a tool. So everything from installing R onwards is built from the floor. **Routed to S52-R2 and taught here only as a doorstep:** writing your own functions and data.table (P1; C05 teaches what a function is and how to call one, C06 names data.table as another package), Git and GitHub (P2, R2; C07 builds the project folder that becomes a repository, C21 names Git as the record of what changed), Quarto and literate programming (P3, R1; C21 and C22 show the hand-copied number and name the document in which code writes it), SQL and DuckDB (P4, R3; the verbs of C11, C16 and C17 are the operations SQL performs, and C17's join is the doorstep), field data tools REDCap, KoboToolbox and ODK (P5; C09 and C22 name them as where a raw file comes from). **Routed elsewhere:** renv and pipeline reproducibility to S52-R3 (the map puts "targets and renv" at rung 3, not rung 2; C21 teaches `sessionInfo()` and package versions as its doorstep and names renv); codebooks as departmental asset protection to S52-R4 (C10 teaches the one-dataset data dictionary); survey weights to S54 (any summary of a survey file in this book is described as unweighted and as not estimating a population figure); missing-data mechanisms and imputation to S15-R2 (C13 teaches counting and reporting missingness only); statistical tests to S03 and S04; visualisation craft to S58 (C18 teaches the grammar and honest axes only). Python is S53. **Versions.** Every printed output in this book is produced by running its code in R 4.3.3 with tidyverse 2.0.0 (dplyr 1.1.4, tidyr 1.3.1, readr 2.1.5, ggplot2 3.4.4, tibble 3.2.1, forcats 1.0.0, lubridate 1.9.3, stringr 1.5.1), readxl 1.4.3, haven 2.5.4, here 1.0.1, renv 1.0.3 and palmerpenguins 0.1.1, installed in this sandbox with no CRAN access; the book says so in C06 and C21. Newer releases exist (opened 2 Oct 2026: R 4.6.1 per the R-intro manual's header; ggplot2 4.0.3, dplyr 1.2.1, readr 2.2.0, tidyr 1.3.2 per their changelogs; renv 1.3.0 on CRAN). Behaviour differences the reader may meet are listed only once read from those changelogs at intake (READY.md). janitor and skimr are not installed and are not used. **Quantitative** is decided by §7a (a concept is quantitative when the reader must carry out a technique whose result can be checked; S36-R1 C05 is the precedent for a non-arithmetic technique), and in a code book almost every section qualifies: 18 of 22. A **problem** here is one of four things: write or fix one line or a short script; predict the output of given code before running it; find the bug in code that runs and gives a wrong answer, or that fails; give the one value a piece of code produces. The ladder maps as follows: levels 1–3, one line on a toy vector or a three-row tibble; 4–6, the same move on the book's dataset with units and labels kept; 7–8, worked code that is wrong (it runs and gives a plausible number, or it stops with an error) for the reader to break; 9–10, a sentence from a thesis, a table or a meeting ("mean BMI was 27.3 kg/m² in the 312 adults") turned into code, run, and followed by what the result does not establish. **Every answer, and every printed output in prose, must be produced by actually running R here**, pasted unedited, and rerun by the auditor; the arithmetic checker cannot see code, so the audit reruns each answer's code from a saved file. Drill sets sit within 3–18 (C02 and C06 small, C11, C12 and C16 largest); `practice_max` stays at the default. The four non-quantitative sections are C01 and C20 (empirical, argued from opened sources), C10 (writing a data dictionary and README, demonstrated by exercises and the build), and C22 (the journey, demonstrated by the build exercise). C22 is the candidate **journey** (`journey: true`): the build target itself, one raw file to one figure and one table by one command. The dataset it runs on is a decision for Harsh at the source gate (READY.md). Type: d derivable, e empirical, i institutional.
